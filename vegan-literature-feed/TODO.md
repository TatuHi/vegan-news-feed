## Still open

- **No curated literature source list.** `scripts/fetch_pubmed.py` only queries PubMed's E-utilities API — there's no `references/sources.md` (the literature equivalent of `vegan-news-feed/references/feeds.md`) curating actual journal RSS feeds across nutrition, animal welfare science, environmental science, and ag/food policy. This would cover the agriculture/environment/policy gap more reliably than the current ad hoc `WebSearch` fallback in `SKILL.md` step 1 — confirmed again on 2026-09-04's real run: both WebSearch queries for that gap returned mostly older background material, nothing fresh enough to include.
- **`fetch_pubmed.py`'s `DEFAULT_QUERY` is a first-pass broad query, and a real 60-day test (2026-08-29, `--days 60 --retmax 40`) quantifies just how noisy.** 40 hits, ~0.67/day (so a 7-day window realistically sees 4-5 raw hits, not zero — volume isn't the concern). But only roughly 30-40% of the 40 titles were genuinely on-topic; the rest was routine veterinary/animal science that happens to match `"animal welfare"[tiab]`/`"animal cognition"[tiab]` as bare keywords with no rights/ethics framing. 12/40 (30%) were correctly flagged as review/meta-analysis, so that part of the design works. This is currently left entirely to the agent's step-2 judgment to filter, same as `vegan-news-feed`'s raw RSS data — but given the real precision numbers, the query itself would likely benefit from narrowing before trusting it at scale. **This is a natural first candidate for `vegan-news-feed-review`-style tuning once that skill is extended to cover this one** (see "Open questions" below) — the data to base a proposal on already exists, it just hasn't been turned into one.
- **Peer-reviewed-only vs. preprints was decided in favor of peer-reviewed-only, but not revisited.** If the "publish first" goal turns out to be poorly served by peer-review's inherent lag, revisit including bioRxiv/medRxiv with clear preprint flagging — this was a deliberate v1 choice, not a permanent one (see `PROCESS.md`).
- **`evals/evals.json`'s 4 entries have never been executed** — written as specs only, same caveat as `vegan-news-feed`'s evals (see its own `TODO.md`).
- **Should `vegan-news-feed-review` also review this skill?** Deferred entirely — not designed, not decided. The review skill currently only knows about `vegan-news-feed`. There's now a concrete motivating example for doing this (the `DEFAULT_QUERY` precision finding above) — a query-quality problem discovered empirically that's exactly the shape of thing that skill already knows how to turn into a proposal.
- **Separate Discord webhook.** Currently shares `vegan-news-feed`'s webhook value (in its own `~/.config/vegan-literature/.env`, at the user's explicit request, for testing convenience). Splitting to a distinct channel is a one-line `.env` edit whenever that's wanted — no code change needed.
- **The LaunchAgent has never fired from the real weekly timer yet** (set up 2026-09-04, Sundays 14:00). The environment-safety mechanics it depends on (pinned Python/`claude` paths, `--add-dir` for cross-directory Write) are already proven — both by `vegan-news-feed`/`vegan-news-feed-review`'s own scheduling history and by this skill's own real manual run the same day — so the residual risk is low, but "low risk" isn't "verified." Worth checking the first real Sunday firing (`~/Library/Logs/vegan-literature-feed.log`, or `launchctl print gui/502/com.tatuhirvonen.vegan-literature-feed.weekly` for last exit code) rather than assuming it worked, same discipline applied to the other two skills' schedules.
