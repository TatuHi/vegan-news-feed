- **Scheduled 2026-08-29 (Sundays 13:15) via a LaunchAgent, but never yet fired by the real timer.** `~/Library/LaunchAgents/com.tatuhirvonen.vegan-news-feed-review.weekly.plist`, loaded with `launchctl bootstrap gui/502`, confirmed registered (`Weekday=0, Hour=13, Minute=15`). Unlike `vegan-news-feed`'s scheduling (`PROCESS.md` iteration 6), this was set up without waiting for a real near-term trigger to prove the mechanism end-to-end — the individual failure modes that bit the daily digest (PATH, Keychain-via-cron, sensitive-file Write) are already independently fixed/verified in this script, but the LaunchAgent trigger path itself for *this* script has not been. Worth checking the first real Sunday firing (log at `~/Library/Logs/vegan-news-feed-review.log`, or `launchctl print gui/502/com.tatuhirvonen.vegan-news-feed-review.weekly` for last exit code) rather than assuming it worked.
- **Add query-term-level contribution/overlap analysis, not just per-outlet.** Motivated directly by `PROCESS.md` iteration 9 (2026-09-02): `feeds.md`'s Google News queries are OR-lists that will keep growing (just went from 3 to 4 terms in the animal-rights query), and nothing currently checks whether an individual term inside a multi-term OR query is still pulling its weight, or has become fully redundant because a newer term already covers everything it used to catch. The existing step-3 "source contribution" analysis only sees the final `source` (outlet name) stored in history — it has no visibility into which *query term* caused a match, so this needs a dedicated mechanism, not just a tweak to existing analysis. The practical approach (same one used manually in iteration 9): split each OR-query into its individual terms, fetch each term separately over a window (e.g. `when:30d`), and compute pairwise overlap — a term whose results are a near-total subset of another term's results is a pruning candidate. This can run on-demand against the live Google News API (doesn't need to wait on accumulated production history) — a good candidate for a small new script, e.g. `scripts/query_term_overlap.py`, that `vegan-news-feed-review` could run and turn into a proposal. Keep the actual `feeds.md` edit human-approved, same as every other proposal — see the "automated and iterative" framing this item came from, and why full autonomy there was explicitly declined, in `PROCESS.md`.
